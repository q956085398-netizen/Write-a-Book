# Write-a-Book
创建一个集拆书（素材积累）、灵感收集、写作为一体的应用。
这不是一个AI一键生成设定、内容的应用，而是AI辅助思考、启发、整理素材，以人的主动记录、思考、写作为主的应用。
不做obsidian的修补匠，而是做一个从零开始的独立应用。
注重理论基础，深度了解理论，从理论中拆分出相应版块的相应功能。
以人性心理来进行功能和前端设计，人性：爱美、怕麻烦、畏难。
因此可以延伸出3个要点：1.UI要美观简洁，让人想要打开应用并停留在上面。2.功能应该就在手边，想要用的时候不需要多次点击、寻找。3.不应该写作之外的构思、设定，不应该是点击“新建”然后出现一个密密麻麻文本框的页面让人对号入座去填表，这样只会让人感到烦躁。
因此需要创新设计，举个例子，图形化设计，假设要在构思板块加一个大纲页签，相比于传统的直接给一个文本框，然后开始写大纲。给用户一个图形化的界面，让用户可以写卡片，卡片可以磁吸，所以可以排列组合，还可以在卡片旁边生出分支，连线到另一张新卡片示意为支线，这样是不是更容易让人接受、更直观也更有趣呢。
因为人的思维不是一条笔直的支线，而是分散的，有时候这里想到一点，那里想到一点，如果是文本框，你就必须“先发生什么，然后发生什么”这样一步步推演下去，这实际上舒服了人的思维优势；以卡片的形式，让用户可以想到什么就先写什么出来，然后再将其组合起来，再对细节进行修改，之后再想到什么，也能很容易地添加进去这不是很好吗。
当然，图形化设计只是一个例子，而不是非要这么做的定式，也不一定能够实现，重要的是理解其中“更人更容易接受、更有利于发挥人思维的优势”的本质。
又比如，写作页面标题部分可以给它加入标签显示这是支线还是主线。
又比如，无论是拆书还是写作，都不时会有灵感跳出，这个时候要怎么设计灵感库和灵感收集页？如何区分专属于这本书的灵感，还有通用的灵感？
又比如，写作的时候不一定都是在写正文，有时候希望会有个便签或者侧页，可以写下这章的目标是什么？情绪是什么？人物有谁？之类的，不要试图定制化统一页面，因为这些会随着写作不断需要修改。

## 本地应用：首章写作路径（T01 / Issue #2）

当前实现资料库选择、新建暂名作品、首章纯文本编辑、自动/手动保存、正常关闭补存与重新打开继续写。核心操作无需账户、网络或 AI 配置。它是完整首版的第一条交付路径，不代表其余模块已完成。

Windows 开发环境需 Node.js 22.12+（或 24+）、Rust MSVC 工具链、Visual Studio C++ 构建工具及 WebView2。

    npm ci
    npm run tauri -- dev

构建本机可运行程序（不生成安装包）：

    npm run tauri -- build --no-bundle

产物：src-tauri/target/release/write-a-book.exe。单独运行 npm run dev 只启动前端页面，浏览器不能访问真实资料库，也不能作为原生验收替代。

验证：

    npm test
    cargo test --manifest-path src-tauri/Cargo.toml --lib
    npm run build
    cargo fmt --manifest-path src-tauri/Cargo.toml -- --check

存储边界、验证记录与尚未完成范围见 [T01 实现说明](docs/t01-first-chapter.md)。
