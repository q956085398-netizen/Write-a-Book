# T03：自动保存失败重试与异常重开恢复

恢复接口、保存/关闭屏障、保存失败横幅、关闭提醒、恢复记录列表、全文图文预览与明确恢复选择已落地。受控检查通过；真实 Windows 恢复路径与原生中文输入法由主会话继续验收，本记录不代表这些验收已完成。

对应 Issue #4 / 父规格 US99—US101。此实现覆盖当前已落地的章节标题、纯文本和图文正文。未实现的内容类型不显示已接入状态。

## 持久化协议

主资料库继续使用 schema 2。每个资料库旁新增 `recovery.sqlite3`，有独立 application_id、schema 1、SQLite FULL 同步和事务；恢复文件随整个资料库目录移动。不会写入浏览器存储或发送远程请求。

一个编辑会话生成随机 UUID，每个完整快照有单调递增序号；同一会话/内容只保留最新完整快照，不同会话保留各自一份。快照包含已确认的完整标题、正文、格式、章节/内容身份，以及编辑基线的完整内容与 revision。不根据时间戳推断先后。日志事务整份更新，失败保留上一份完整记录。字节长度、FNV-1a 64 位校验与 SQLite quick_check 用来发现意外损坏；校验不是签名、加密或防恶意篡改承诺。格式或完整性不能确认时保留原文件并拒绝应用。

已完成输入约每 300 毫秒写恢复快照，停输约 1 秒、连续输入约 5 秒通过同一串行保存链更新主库。主库写入前先等待完整恢复快照落盘；只在主库真实提交回执后显示已保存。失败保留当前输入和持续错误提示，约 5 秒自动重试，也可主动重试。作者继续打字不会清除错误。作者撤销回已保存内容时，也会更新恢复快照，避免再次恢复已撤销内容。

主库仍按 expectedRevision 条件更新标题和正文。已提交但回执丢失时，完全相同的正文、标题和格式可返回实际 revision，不重复覆盖或递增。日志清理只针对已确认持久化且完整内容匹配的会话序号，不删除较新的草稿；清理失败时重开比较完整内容，避免把已提交内容再次当作待恢复稿。

恢复只承诺找回**已完整持久化、能确认完整性的最新本地快照**。从未落盘的最后按键、未确认的输入法候选、同时损坏的主库与日志，以及无法确认完整性的文件都不在这一保证内。日志与主库在同一磁盘，不能充当异盘备份；日志写入本身失败时明确显示尚未留存。

## 版本选择与图片

草稿的完整基线与当前主库版本都相同时，才允许作者确认接续原章节；真正应用前再次检查预览时的草稿序号、完整基线与 revision；草稿在预览后发生变化时要求刷新重新查看。任一字段不一致或基线不可读取时视为先后不明，保留当前主库与恢复草稿，不能覆盖原章节，只能另存为恢复作品。

恢复副本生成新的作品、章节与 contentId。受管图片复制到新的随机附件 ID，文件写入并 sync 后，在同一 SQLite 事务中登记副本正文、章节、作品和附件归属。原图、原章节和未成功应用的日志均保留。图片缺失或无法读取时拒绝恢复，不显示成功。本分支的副本协议及原有失败证据保持不变；主会话另以 ec4163e 增加本次创建附件的失败清理。本文不将该后端改进宣称为本 UI 分支已验证内容。恢复不自动发送任何 AI 请求。

主库冲突不应阻止进入恢复副本：专用恢复屏障先完整留存当前输入，再允许替换编辑器中的当前版本。完整留存失败或仍在中文组合输入时停留原处。普通作品/资料库切换和正常关闭继续使用主库保存屏障。

## 中文输入与关闭

保存、切换、新建作品与关闭不主动 blur 输入框；组合输入尚未结束时停留并提醒作者确认候选。保存途中开始新的组合输入也不能绕过关闭屏障。切换失败后不自动转移焦点，鼠标点击操作按钮不通过失焦强制提交候选。图片导入中的关闭/切换等待附件任务结束再取最终快照。

## 视觉与关闭提醒

2026-10-17 按主会话从已付费转换取回的 `recovered-writer/a.html` 及原 `screens/a.png` 接入保存失败横幅和关闭提醒。采用导出的玫瑰色提示面、6 像素圆角、约 440 像素白色对话面板、12 像素面板圆角、约 31 像素内边距与绿色主操作；文字允许换行以适应窄窗口。保留既有最小工作台、本地字体与真实功能，未导入演示头像、章节、未实现导航、网络保存文案或远程字体。

错误条只在真实失败尚未解决时出现，按恢复回执区分“完整草稿已留存”“仍在更新”“尚未完整留存”。关闭失败时取消该次关闭，非组合输入期间显示“继续编辑 / 重试保存并关闭”；提示面板保持焦点边界。中文组合输入期间只作内联提醒，保持候选焦点。后台重试成功只更新为“内容已保存，可以关闭”，不会替作者继续此前失败的关闭操作。

恢复页按同一原 run 的 `screens/b.png` 接入：当前窗口完整正文与所选本地草稿并排显示，安全接续使用绿色边框与操作，先后不明使用琥珀色标签，并保留恢复说明区；窄窗口改为顺序纵排。没有引入演示章节、时间戳、云保存、删除、历史或备份功能。A 保存失败横幅新增“查看恢复记录”，侧栏始终保留同名入口；启动时发现记录只提示作者核对，不自动应用。

恢复记录可选择并刷新，每条显示真实快照序号、完整性和基线状态。当前窗口、记录对应的资料库当前版本（内容不同时）与所选草稿均为全文只读预览，可滚动查看与复制；没有省略号截断。支持常用段落格式及经本地受管接口读取的图片，读取失败有明确提示。未知正文格式显示完整原始正文，只读保留且禁用恢复操作。

“继续此版本”只对可识别、完整性确认且基线一致的记录出现；完整但先后不明时仅允许“另存恢复作品”。恢复入口和操作使用 `preserveForRecovery`，成功回执后用 `loadRecovered` 装入，所以主库 revision 冲突不会迫使作者先覆盖当前版本。草稿更新、图片复制或主库写入失败保留对照与原始内容，刷新后可以重新核对；恢复副本读取自己的新 contentId/附件身份，不复用原章节的图片身份。中文组合输入期间仅显示内联提醒，不打开恢复页或抢焦点，按钮鼠标按下也不强制候选提交。

b/c 转换在原版、隔离新版与续取尝试中返回 upstreamunavailable；用户明确批准“允许依现有设计完成，注明未验证项”，本次据此使用已生成的 a/b 原图与已取回的 A 导出实现。没有新的外发或付费转换。本次仅有设计源依据与组件行为检查；未在浏览器或原生窗口检查实际排布，也未执行最终 12ui improve 对照。外部转换与像素对齐未验证，不能把组件测试说成屏幕对齐通过。

## 后续契约

新增笔记、构思、布局与未发送 AI 草稿时，须接入相同的完整快照、确定基线、顺序写入、真实回执和恢复选择规则；须为每种内容补充格式/依赖完整性校验。布局恢复与文字/关系作用范围需要按后续规格区分，不能直接套用章节覆盖。草稿恢复只能恢复本地状态，不触发 AI 发送。

历史、搜索、回收站、完整备份尚未落地，保留为后续接入项。本恢复日志不是历史列表或完整备份；没有因此缩减父规格要求。附件继续沿用现有受管图片归属规则。
