# T05：多作品、可选分卷与正文片段

对应 Issue #6，父规格 US4、US75、US76。此实现覆盖作品的书架和紧凑列表、每部作品上次打开的章节或片段、可选分卷、章节与分卷排序、章节跨卷移动、未编章片段独立图文编辑，以及作者确认后“编为新章节”。不把这一步交付描述为完整首版完成。

## 作者操作与保存

作品书架和紧凑列表显示相同的真实作品与继续位置，无封面时使用排版书封，不填充虚构照片、简介、进度或字数。空名称可新建“未命名作品”，直接进入第一章。继续位置按作品保存记录身份；它指上次打开的正文条目，不承诺光标、选区或滚动位置恢复。

左侧只有一份卷章与片段目录。新建章节可选择目录顶层或现有卷，分卷可暂名且可改名。章节与卷都能上移、下移；“调整目录位置”可指定目标卷或目录顶层，以及目标兄弟项之前或目录末尾。卷不能嵌套进卷。未编章片段先独立写作，稍后选择“编为新章节”并明确位置；界面确认它从片段区移出且文字、图片保留，不暗示 AI 创作。

切换作品、章节、片段、资料库、进入书架和开始结构操作，均先等待现有 EditorSession 的完整草稿、受管图片任务与主库保存成功。正文失败时保留当前内容、持续错误和既有重试入口，不提前换目录或选中。结构确认只在 SQLite 提交回执成功后更新界面；失败保持对话、原目录和当前正文，作者可重试或取消。尚未确认的目录名称不显示已保存；窗口关闭先要求保存或取消这次目录操作。

沿用现有 DOM 组合状态屏障，组合尚未结束时不启动结构操作、不主动失焦。这里的组件检查不能证明原生候选焦点保持；Issue #4 仍开放，本轮不包含 IME 平台修复。

## 稳定身份和移动语义

- 章节和片段共用原有 chapters 记录与 contents 正文。kind 区分 chapter / fragment；可选 volume_id 只是章的目录归属。标题不是身份。
- “编为新章节”修改同一条记录的 kind、volume_id、position，保留原 entry id、contentId、正文、格式、正文 revision 及图片附件归属。不创建第二份正文、不删除原正文，也不拼接到已有章节后保留重复稿。
- 章节重排、跨卷移动、卷重排和改卷名都只修改结构元数据。结构 revision 与正文 revision 分开；结构操作不递增正文 revision。每部作品的 structureRevision 参与事务内条件更新，拒绝过期目录、跨作品源或目标、失效目标位置。
- 目录顶层按 position 混合排列卷和不分卷章节；卷内按章节 position 排列。片段不属于任何卷，在独立片段区排列。编章先移出片段集合，再插入指定目标位置；一个 contentId 始终只对应一条正文记录。
- 后续导出应按根目录顺序遍历：卷名后接卷内章节，不分卷章直接输出；默认排除 kind=fragment，只有作者主动选择片段及位置后纳入。当前不显示导出入口，也未实现导出。
- 后续净增按 contentId 的实际文字编辑计算；创建空条目不产生字数，编章、目录重排与跨卷移动均为零净增，不能因新进入章节集合而把片段原文字数算作新写。本轮没有启用净增、计时、目标或写作记录。

所有结构变更和作品继续位置在主库 SQLite FULL 同步事务中提交；失败或未提交事务保留上一份完整结构，不需要用正文恢复快照覆盖目录。正文标题与内容则继续通过 T03 的 expectedRevision、完整恢复快照、串行主库写入和真实保存回执。

## schema 3 与恢复兼容

打开受支持的 schema 1/2 时先检查 application_id、quick_check、必需列类型与稳定主键、现有正文/作品关联、目录位置及外键数据。重复旧顺序、缺失关系或无法确认的结构拒绝迁移。旧版本升级、分卷表、新列、作品继续位置和 user_version=3 在一个 IMMEDIATE 事务里完成；任一步失败回滚。ALTER 保留未知旧 metadata；迁移按稳定 id 和 contentId 关联，完全同名的作品或章节也不会合并。旧库原位置可能有未归一的 position；首次整理或追加时以已有顺序归一，不据标题重排。

chapters 新增 kind（默认 chapter）和 volume_id，新增 volumes 与 work_state。主库内容 DTO Chapter 和 recovery.sqlite3 schema 1 的 JSON 快照不新增必填字段，所以旧恢复 payload 可原样读取、比较与接续。正文片段使用同一 checkpoint/save/acknowledge/recover 路径，现有图文校验与 contentId 图片边界不变。编章前留存的正文快照在结构移动后仍可比较并接续，不把目录移动当成正文冲突。

冲突另存恢复作品仍生成新的作品、entry、contentId 和图片附件身份；源记录与图片完整保留。源仍存在时按 entry/content 身份读取当前 chapter/fragment 类型并保留到副本；无法定位的旧来源沿用独立章节回退。恢复副本不携带旧卷归属或影响原作品结构。新增 INSERT 均指定列名，避免 chapters 列数变化破坏新建作品与恢复副本。

历史、搜索、回收站、日常完整备份及整库迁移尚未落地；新增结构、正文片段与其图片必须在这些后续功能中按同一稳定身份接入。本地恢复日志不等于历史或完整备份；本轮未增加删除或假入口，不缩减父规格的上述要求。

## 设计依据与验证边界

主会话使用已批准 A 及本轮纯虚构说明运行 12ui branch。a 编辑/卷章、b 书架、d 片段编章图生成；c 紧凑列表 provider_error，a/b/d HTML 转换均 upstream unavailable，原 A 复用也被拒绝，未取得可用新 HTML。用户明确允许故障时沿用现有 A 并记录未验证项。因此本轮沿用现有 App/styles 与原 A.html 的本地字体、纸色、分隔线和绿色操作；已查看 a/b/d 图作交互组织参考。移除了错品牌、云状态、虚构封面与统计、未实现导航、重复目录和硬性 20 字限制。

外部转换、最终 12ui improve 对照及像素复现未验证。这里没有外发源代码或实际屏幕截图；书架和目录组件不是生成图的逐像素实现。

本轮实现代理只在独立 worktree、签入 Windows 用户的逐命令审批环境运行含真实进程的测试，使用临时目录和虚构内容；未访问实际 AppData 或用户资料库，未启动 GUI、安装或杀进程。最终计数在提交前复核：

- Rust 临时 SQLite / 本地受控 API 套件：33 项通过，含旧 schema 1/2 同名记录与额外 metadata、旧 recovery payload 接续、迁移失败原数据库字节不变、可选卷章顺序、跨作品拒绝、结构过期/失效位置/写入失败事务保旧、同身份图文编章及重开、未编章片段保存失败日志重开与冲突副本。受控触发器失败不能代表实际磁盘耗尽、断电或进程强退。
- React/JSDOM 全套：62 项通过；T05 新增 7 项覆盖书架/列表继续位置、实际 App 保存屏障、新片段保存身份、原图文编章、结构失败保持/重试、卷与章节移动、DOM 组合状态及未完成目录操作关闭保护。JSDOM 的布局边界替身只供 ProseMirror 焦点滚动使用，不作为视觉或原生输入法证据。
- TypeScript/Vite 生产构建与 Rust 格式检查通过；保留既有 Tiptap use-client 和大脚本提示。

真实 Windows 应用操作、原生中文候选、正常关闭重开后的可见卷章/片段/继续位置、实际图片导入和结构失败提示、窄窗口与最终整合截图由主会话串行验证并另补证据。它们在本实现代理记录中均为未验证。安装升级、导出与净增也未在本轮验证。
