# T01：新建作品、写首章并重开找回

本项对应 Issue #2，仅实现第一条本地写作路径。未实现的富文本和图片编辑（#3）、完整异常退出恢复（#4）、历史、搜索、备份、迁移、安装/升级仍按后续任务接入，不提供假入口或成功状态。

## 应用操作与保存

React 使用 ApplicationPort 访问 Tauri 的统一应用操作：启动恢复、选择资料库、新建作品、选择作品、保存章节。Rust Application / Library 是同一持久化边界，数据集成测试直接使用这些操作。UI 无数据库查询或本地浏览器存储。

作品、章节、正文各有 UUID，正文独立保存为 content 记录，章节引用它。重名不会合并。资料库中有 library.sqlite3 与受管理的 attachments/ 目录；本项只建立附件扩展位置，尚无导入、引用或附件清理功能。SQLite schema v1 与 application_id 会在打开时校验，未知/外来数据库拒绝打开。

首次启动可接受“文档/写一本书资料库”或选择文件夹。最近资料库路径保存在 Tauri 应用配置目录中的 settings.sqlite3；上次位置缺失时提示重新选择，不创建替代空库。所选资料库失败不会替换当前资料库。界面展示实际路径。目录移动与备份不是此操作的含义。

正文和章节标题停输约 1 秒保存；连续输入约 5 秒保存已确认的输入；中文输入法组合期间不保存未确认输入，周期已到则在组合结束后补存。Ctrl+S、保存按钮、作品/资料库切换和正常关闭共用 EditorSession.flush()。保存中的新输入会继续补存，已保存状态只由持久化回执确定。正常关闭先取消窗口关闭，输入框失焦提交组合输入，待保存队列完成才销毁窗口。失败保留当前输入、显示错误并允许重试，阻止该次切换/关闭。本项不宣称可恢复尚未持久化且被系统强制终止的内容。

SQLite 同步级别为 FULL，正文和标题在一个事务中更新，版本条件避免过期窗口覆盖已修改内容。保存回执在同一事务内取得，提交后才返回。冲突时保留输入并提示先复制文字再重新打开；完整冲突恢复界面属后续任务。

字数使用 Unicode code point 计数，排除空白，包含标点与 emoji；标题不计。当前仅首章，尚无分卷、多章管理或全书统计。

## 自动检查与验收边界

自动检查以真实临时 SQLite 文件验证新建、中文/混合文本保存、释放连接后重开、身份保持、继续编辑、同名作品、路径缺失、选择失败保留当前资料库和过期保存拒绝。前端测试模拟持久化边界确认作者可见保存状态、失败保留、组合输入、连续输入与并发保存。

这些检查不能证明 Windows 输入法、原生目录对话框、真实窗口关闭重开或视觉体验。已执行的真实 Windows 验收见下方记录；未覆盖项目仍保留为未验证。

手动验收步骤：

1. 在 Windows 原生应用首次启动，选择独立空目录作为资料库，不配置账户或 AI。
2. 新建暂名作品，输入中文标题与两段正文，观察停输后的本地保存状态和字数。
3. 输入新句后立刻正常关闭窗口；重开确认最新完整内容、作品与章节仍可编辑。
4. 再编辑、保存、关闭重开，确认第二次修改仍在。
5. 通过真实中文输入法检查组合输入、候选确认和光标位置；记录工具只能直接输入中文时的覆盖限制。
6. 记录窗口尺寸、测试资料库位置、实际构建与退出方式，区分本地离线核心与离线安装（未验证）。
